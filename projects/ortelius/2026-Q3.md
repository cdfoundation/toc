# Ortelius Project Update – 3rd Quarter 2026

## Features and Release

Ortelius continues to advance its capabilities for continuous software supply chain security, with a focus on post-deployment vulnerability detection, application-level SBOM correlation, and AI-assisted remediation.

Current development priorities include:

- **Continuous vulnerability management:** Correlating newly disclosed CVEs with software packages, application releases, and deployed endpoints.
- **AI-assisted CVE remediation:** Developing capabilities to identify safe dependency upgrades, validate changes through application builds and tests, and generate pull requests or GitHub issues.
- **Developer experience:** Improving local builds, front-end development workflows, and contributor onboarding.
- **Software supply chain visibility:** Continuing to improve the correlation of SBOMs, vulnerability intelligence, and deployment metadata.
- **Simplified onboarding:** Streamlining the process of connecting repositories and collecting software supply chain information without requiring CI/CD plugins.

Project development is available in the [Ortelius GitHub repository](https://github.com/ortelius/ortelius).

## Security Updates

### CVE remediation

The Ortelius team clean up over 40 CVEs, 8 of them critical - 4 of which where identified post-release. We continue to use Ortelius to check Ortelius releases for newly reported CVEs. 

### AI-Assisted CVE Remediation

Ortelius is expanding its work beyond vulnerability detection to explore AI-assisted remediation.

The [CVE Reasoner Engine](https://youtu.be/tyspotuzAqs?si=3074a8tmJiu06SDO), developed for the AllDayAI Hackathon, demonstrates a workflow that combines AI reasoning with deterministic validation and human oversight.

The prototype is designed to:

- Identify vulnerable dependencies and recommended safe versions.
- Attempt automated dependency upgrades.
- Run application builds and tests to validate changes.
- Generate GitHub pull requests for successfully validated fixes.
- Create GitHub issues when vulnerabilities require developer intervention.

The approach emphasizes validating changes before declaring remediation successful. When a safe upgrade cannot be completed automatically, the remaining work is documented for developer review.

This work supports Ortelius' long-term goal of reducing the time between vulnerability disclosure, identification of affected deployed applications, and verified remediation.

[Learn more about the CVE Reasoner Engine](https://ortelius.io/blog/2026/10/23/ortelius-alldayai-hackathon-ai-cve-remediation/).

## Infrastructure Updates

### Streamlined Onboarding and Plugin-Free CI/CD Integration

Significant improvements have been made to simplify Ortelius onboarding and reduce the effort required to connect development environments to the platform.

**Ortelius no longer requires CI/CD plugins to onboard repositories and collect software supply chain information.**

These improvements are designed to:

- **Simplify onboarding:** Reduce the number of configuration steps required to begin using Ortelius.
- **Eliminate CI/CD plugin dependencies:** Allow teams to connect their development environments without installing or maintaining dedicated CI/CD plugins.
- **Reduce integration overhead:** Minimize changes to existing build and deployment pipelines.
- **Improve accessibility:** Make Ortelius easier to adopt across different development environments and CI/CD platforms.
- **Support broader adoption:** Lower technical barriers for organizations with limited DevOps resources.

These changes support Ortelius' goal of providing software supply chain visibility without requiring teams to touch their existing CI/CD workflows. They also make it easier for new users and contributors to evaluate Ortelius and begin exploring its vulnerability management capabilities.
