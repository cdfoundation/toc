# CDEvents Update

This update covers the second and third quarters of 2026.

## Features and release

The project also started modelling the concepts used in links as schemas, so that SDKs and users
can share and validate them:

- Links can now reference a domain-level identifier (`domainId`), a CDEvent context ID, or both.
  This change also introduced a governed registry of providers
  ([spec#292](https://github.com/cdevents/spec/pull/292), merged).
- Spinnaker is being added to the provider registry
  ([spec#334](https://github.com/cdevents/spec/pull/334), in review).
- A registry of resource types for the `type` segment of `domainId`
  ([spec#335](https://github.com/cdevents/spec/pull/335), in review).

Other changes merged in the spec for v0.6:

- A new `queued` predicate for `taskRun`
  ([spec#317](https://github.com/cdevents/spec/pull/317)), contributed by a new contributor.
- A consistency fix for the `taskRun.finished` event
  ([spec#304](https://github.com/cdevents/spec/pull/304)).

New proposals under discussion include changes to the deployment events, subjects and events
for scheduled executions, change windows, data migrations and reconciliation, an optional
canonical hash for event integrity, and event types for feature flags and SCM branch pushes.
The project communnity  is aiming for a v0.6 release after these proposals are reviewed.

Releases:

- Spec [v0.5.1](https://github.com/cdevents/spec/releases/tag/v0.5.1) (April 2026)
- [Rust SDK v0.4.0](https://github.com/cdevents/sdk-rust/releases/tag/cdevents-sdk-v0.4.0) and
  [v0.4.1](https://github.com/cdevents/sdk-rust/releases/tag/cdevents-sdk-v0.4.1), with support for
  spec v0.5.1
- [Go SDK v0.5.1](https://github.com/cdevents/sdk-go/releases/tag/v0.5.1), with support for spec
  v0.5.1 and bug fixes

## Contribution trends

In Q2 and Q3 contributions to the spec increased, with several new event proposals.
Contributions to the SDKs were mostly maintenance and bug fixes.

## Security updates

- The Rust, Go and Java SDKs added a [Plumber](https://getplumber.io) security scan to CI and
  hardened their GitHub Actions workflows.
- The project communnity is discussing event-level provenance and tamper evidence
  ([spec#315](https://github.com/cdevents/spec/issues/315),
  [spec#320](https://github.com/cdevents/spec/pull/320)), in light of the
  [verifiability extension](https://github.com/cloudevents/spec/blob/main/cloudevents/extensions/verifiability.md)
  recently merged in CloudEvents.
