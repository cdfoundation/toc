# CI/CD Cybersecurity Guide Project Update – Q32026

## Features and release

The CI/CD Cybersecurity Guide continues to expand its coverage of cybersecurity frameworks, regulatory requirements, and practical open-source security tooling across the software delivery lifecycle.

The project has completed its initial mapping of open-source security tools to the NIST Secure Software Development Framework (SSDF) and is now expanding into two important new areas: the European Union Cyber Resilience Act (CRA) and AI Security in the CI/CD Pipeline.

### New Chapter: EU Cyber Resilience Act (CRA)

The project is developing a new chapter that maps CRA cybersecurity requirements to practical DevSecOps activities and open-source tooling.

The chapter is organized around the three phases of the CI/CD lifecycle:

- **Phase 1 – Code and Prebuild:** Cybersecurity risk assessments, secure-by-design development, dependency management, and vulnerability disclosure preparation.
- **Phase 2 – Build and Deploy:** Release security validation, SBOM generation, artifact integrity, secure distribution, and compliance evidence.
- **Phase 3 – Post Deployment:** Continuous vulnerability monitoring, affected-product identification, remediation, security updates, and vulnerability disclosure.

The goal is to help development and platform engineering teams understand how to implement CRA-related security requirements using accessible open-source tools.

### New Chapter: AI Security in the CI/CD Pipeline

A second new chapter addresses the emerging cybersecurity challenges introduced by AI-assisted development, autonomous agents, and AI-powered applications.

This chapter also follows the three phases of the CI/CD lifecycle:

- **Phase 1 – Code and Prebuild:** Securing AI-generated code, autonomous development agents, model dependencies, datasets, and development environments.
- **Phase 2 – Build and Deploy:** Validating AI-generated changes, protecting AI artifacts, verifying model integrity, and securing AI application deployment.
- **Phase 3 – Post Deployment:** Monitoring AI applications, auditing autonomous agent activities, detecting AI-specific threats, and managing vulnerabilities in deployed AI systems.

The chapter draws on established guidance, including NIST SP 800-218A, the NIST AI Risk Management Framework, and OWASP guidance for LLM applications.

Both chapters are being developed collaboratively, with open-source tooling tables intended to help DevOps teams select practical tools for implementing security controls.

### Expanded Educational Resources

The project has also added educational and reference materials covering:

- European Union Cyber Resilience Act regulations and implementation guidance.

These resources are intended to help organizations understand cybersecurity requirements and identify practical implementation options.

## Community updates

### CI/CD Cybersecurity Guide Accepted as a CDF Project

On November 3, 2026, the Continuous Delivery Foundation announced the acceptance of the CI/CD Cybersecurity Guide as a new open-source project.

Originally developed through the CDF CI/CD Cybersecurity Special Interest Group (SIG), the initiative has grown beyond its original scope.

After completing the initial NIST SSDF mapping, the community recognized the opportunity to create a broader, ongoing resource connecting cybersecurity frameworks with practical open-source tooling.

The project now provides a community-driven platform for developing and maintaining guidance that helps organizations implement cybersecurity controls throughout the software delivery lifecycle.

### Community Collaboration

The project is encouraging greater collaboration across the CDF ecosystem, particularly with:

- **CDF AI SIG:** Addressing AI-assisted development, autonomous agents, and AI security within software delivery pipelines.
- **CDF Platform Engineering SIG:** Exploring how security controls and open-source tooling can be incorporated into platform engineering practices and Golden Paths.
- **OpenSSF and CNCF communities:** Identifying existing open-source security tooling and encouraging collaboration across projects.

The goal is to provide a practical, vendor-neutral reference for organizations building and securing their software delivery environments.

### Expanding Security Guidance Beyond Traditional CI/CD

The project's security focus has expanded to address two significant developments affecting software delivery teams.

**1. EU Cyber Resilience Act**

The new CRA chapter helps organizations understand how cybersecurity requirements apply throughout the software lifecycle.

Particular attention is being given to:

- Secure-by-design development.
- Software component transparency and SBOMs.
- Vulnerability identification and remediation.
- Security updates and coordinated vulnerability disclosure.
- Maintaining security after deployment.
- Documenting evidence of cybersecurity practices.

**2. AI Security**

The new AI Security chapter addresses risks introduced by AI-assisted software development and autonomous agents.

Key areas include:

- Security validation of AI-generated code.
- Agent identity, permissions, and access controls.
- Prompt injection and sensitive information exposure.
- AI model and artifact integrity.
- Security testing of AI applications.
- Monitoring deployed AI systems.
- Human oversight of AI-driven changes and remediation.

Both chapters emphasize the use of open-source tools to implement practical security controls.

The project continues to reinforce an important principle: **Security does not end when software is deployed. Continuous monitoring, vulnerability management, and remediation are essential parts of secure software delivery.**
